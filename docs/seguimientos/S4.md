## Instalación desde cero

Persona 4 no configuró la instalación (Docker, Codespaces y el servidor los preparó la Persona 1) y
siguió solo el README, el 28 de octubre de 2026, en su computadora con Windows 11 y sin Docker. Cada
pasada empezó en una carpeta nueva, con las bases vacías: PHP 8.1.34 recién descomprimido, con el
`php.ini-development` que trae PHP; MongoDB 7.0.14 y Redis 7.2.16 para Windows.

### Primera pasada: el README de `main`

`git clone` del repositorio (commit `74d5e1d`) y la opción «PHP instalado en la computadora», al pie
de la letra.

| Paso | Qué pasó | Corrección |
|---|---|---|
| Requisitos: «PHP 8.1 o superior con la extensión `mongodb`» | Con solo esa extensión, `probar_conexiones.php`, `crear_esquema.php` y `cargar_datos.php` terminaron bien, pero el portal, el inicio de sesión y el registro daban error 500 (`Call to undefined function mb_substr()`, `mb_strtolower()` y `mb_strlen()`). Subir imágenes, además, necesita `fileinfo`. | El README pide `mbstring` y `fileinfo`, y `probar_conexiones.php` avisa si falta alguna; antes decía que todo estaba bien. |
| Activar las extensiones en Windows | El README no decía cómo ni de dónde sacar `php_mongodb.dll`. Si `extension_dir` queda comentado, PHP las busca en `C:\php\ext` y no carga ninguna. | Notas para Windows en el README: qué líneas del `php.ini` activar y qué zip de la extensión `mongodb` bajar. |
| «Con MongoDB y Redis corriendo en la misma máquina» | No decía cómo tenerlos en Windows, donde Redis no tiene versión oficial, ni que se puede trabajar sin Redis. | Notas para Windows (MongoDB con el instalador `.msi`; Redis con WSL o Docker) y `REDIS_DESHABILITADO=true` para trabajar sin Redis. |
| `cp .env.example .env`, `probar_conexiones.php`, `crear_esquema.php`, `cargar_datos.php --limpiar` y `php -S …` | Funcionaron tal cual, en Git Bash. `crear_esquema.php` y `cargar_datos.php` tardaron 0,3 s cada uno, y `/estado` dijo «Funcionamiento normal». | El README dice que en el símbolo del sistema (`cmd`) se usa `copy` en lugar de `cp`. |
| ¿Quedó bien instalado? | El README no decía cómo comprobarlo. Con `php scripts/pruebas/correr.php`: 16 pruebas pasan, 0 fallan y 2 se omiten (EC-02 y EC-05, que necesitan detener un motor). | Sección «Comprobar la instalación» en el README. |

### Segunda pasada: el README nuevo

Con los cambios de este seguimiento, en otra carpeta y otra vez con las bases vacías, se siguió la
opción C del README nuevo, y el esquema se creó con mongosh (`scripts/mongosh/crear_esquema.js`) en
lugar de `crear_esquema.php`. Como los cambios todavía no estaban en GitHub, en lugar del `git clone`
se copiaron los archivos de la copia de trabajo.

| Paso | Resultado |
|---|---|
| `php scripts/probar_conexiones.php` | «extensiones mbstring y fileinfo: activas»; MongoDB 7.0.14 y Redis 7.2.16 respondieron. |
| `mongosh --nodb --quiet scripts/mongosh/crear_esquema.js` | Leyó la URI del `.env` y creó las 5 colecciones con su validador y los 14 índices. |
| `php scripts/cargar_datos.php --limpiar` | 6 organizaciones, 67 usuarios, 42 actividades, 350 inscripciones y 12 avisos. |
| `php -S localhost:8080 -t public public/index.php` y `/estado` | «Funcionamiento normal». |
| `php scripts/pruebas/correr.php`, completo (10 min 5 s) | 16 pruebas pasan, 0 fallan y 2 se omiten (EC-02 y EC-05), igual que en el servidor el 26 de octubre: la aplicación funciona sobre el esquema que creó mongosh. [Informe](../pruebas/resultados/pruebas_20261028_191605.txt). |
| `php scripts/crear_esquema.php`, sobre la misma base | Los 5 validadores, «actualizados», y los 14 índices, «(ya existían)»: los dos scripts crean lo mismo. |

Sobre esta misma instalación se hicieron a mano los pasos que el script omite: los de EC-01, EC-02,
EC-05 y EC-06 con un motor detenido, y el paso 3 de CN-03 (ver
[Pendientes anteriores que se cerraron](#pendientes-anteriores-que-se-cerraron)).

  y mostró «El tiempo terminó…» sin recargar la página ([caso normal](../pruebas/caso-normal.md)).
- **Tiempo de carga de los datos de prueba (pendiente desde S2):** `cargar_datos.php --limpiar` tarda
  0,3 s en la instalación local.

## Qué quedó pendiente y por qué

- **Opción A (Docker) desde cero:** ver [Lo que falta](#lo-que-falta).
- **Tipo de máquina de las mediciones:** no quedó anotado el 26 de octubre y Codespaces no lo guarda.
  Para saberlo habría que repetir las mediciones. Las conclusiones no dependen de él, porque cada
  medición compara los dos modos en la misma máquina y en la misma corrida.
- **Video (#39) y presentación (#40):** el grupo los prepara aparte; no están en el repositorio.

## Bloqueos

Ninguno. Los motores del servidor del curso siguen sin poderse detener, así que los pasos de EC-01,
EC-02, EC-05 y EC-06 que necesitan uno caído se repitieron en la instalación local.

## Decisiones técnicas tomadas

Detalle en [docs/decisiones.md](../decisiones.md).

1. **D26. El esquema también se crea con mongosh, que lee la URI del `.env`.** El script abre la
   conexión él mismo (`mongosh --nodb`), así la URI y su contraseña no se escriben en la terminal ni
   quedan en el historial. El esquema queda escrito dos veces, en PHP y en JavaScript; el 28 de
   octubre se compararon las dos bases que crean y quedaron iguales.
